# Voxel Fracture Lab Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans for the scoped tasks below.

**Goal:** Build and run a small C voxel fracture sandbox with crate explosion and rigid beam failure.

**Architecture:** Pure C voxel graph and application; raylib 5.5 renders cubes and controls. A narrow C ABI over Jolt 5.3.0 provides compound rigid bodies and ground collision. GNU Make builds all source dependencies locally.

**Tech Stack:** C11, C++17 adapter, GNU Make, Python 3 bootstrap, raylib 5.5, Jolt 5.3.0.

**Spec:** ../specs/2026-11-05-voxel-lab-design.md

## Global Constraints

- Work only inside PixPhysiccc; preserve existing parent repository changes.
- No visible deformation; integer graph strengths/damage and beam load estimates.
- One rigid body per connected component; fixed-step collision simulation.
- User has approved implementation and fetching dependencies; continue without additional approval gates.

## Review Focus

- A broken bridge must split topology even when some bonds survive.
- Subthreshold static beam load must not accumulate damage over time.
- Crate resets and repeated scene switches must release rigid bodies.
- Fragment splits must retain mass and parent motion; empty/invalid bodies must fail cleanly.
- A freshly fetched build must work through Makefile on the available Windows MinGW toolchain.
